## PR01-01 — Verificação de ISBN condicionada também ao título

| Campo | Conteúdo |
|---|---|
| Requisito | RF01 / CA02 — ISBN obrigatório e único |
| Dificuldade esperada | Média |
| Categoria | Consulta / integridade |
| Localização | `BookService.createBook`, linha 11 |
| Causa-raiz | A busca de duplicidade usa ISBN **e** título (`findOne({ isbn, title })`); só encontra o registro quando os dois coincidem. |
| Comportamento esperado | Qualquer cadastro com ISBN existente é rejeitado (`ISBN_ALREADY_EXISTS`, 409) e o acervo não muda. |
| Comportamento observado | ISBN repetido com título diferente é aceito (201); o acervo fica com dois livros de mesmo ISBN. |
| Implementação correta | `const existingBook = await this.bookRepository.findOne({ isbn });` |
| Implementação defeituosa | `const existingBook = await this.bookRepository.findOne({ isbn, title });` |
| Teste-oráculo | `PR01-01.test.js` — cadastra "Estruturas de Dados" (ISBN 978000000001); tenta cadastrar "Estrutura de Dados" com o mesmo ISBN; exige `ISBN_ALREADY_EXISTS` e acervo idêntico ao anterior. |

## PR01-02 — Persistência realizada antes de todas as validações

| Campo | Conteúdo |
|---|---|
| Requisito | RF01 / CA03, CA04, CA05; RN08 — rejeição não altera o estado |
| Dificuldade esperada | Alta |
| Categoria | Efeito colateral / ordem de execução |
| Localização | `BookService.createBook`, `save` nas linhas 17–23, validações nas linhas 25–31 |
| Causa-raiz | O livro é persistido antes das validações de ISBN/título/autor e de quantidade; o erro só é lançado depois que o registro já existe. |
| Comportamento esperado | Cadastro inválido é rejeitado sem criar registro. |
| Comportamento observado | A API responde 400 (`INVALID_BOOK`/`INVALID_QUANTITY`), mas o livro inválido permanece no acervo. |
| Implementação correta | validações → checagem de duplicidade → `return this.bookRepository.save({...})` |
| Implementação defeituosa | checagem de duplicidade → `const book = await this.bookRepository.save({...})` → validações → `return book` |
| Teste-oráculo | `PR01-02.test.js` — acervo com 1 livro válido; cadastro com título vazio e quantidade válida (ISBN novo); exige `INVALID_BOOK` e acervo idêntico ao anterior. |

## PR01-03 — Cliente consegue definir a disponibilidade inicial

| Campo | Conteúdo |
|---|---|
| Requisito | RF01 / CA01 — disponível inicial = total; RN09 |
| Dificuldade esperada | Média |
| Categoria | Estado / mass assignment |
| Localização | `BookService.createBook`, linha 22 |
| Causa-raiz | `availableCopies` é lido da entrada quando informado (`input.availableCopies ?? totalCopies`), em vez de derivado de `totalCopies`. |
| Comportamento esperado | `availableCopies` inicial sempre igual a `totalCopies`; valor enviado é ignorado. |
| Comportamento observado | `totalCopies: 5, availableCopies: 1` gera livro com 1 disponível. |

## Apoio à classificação das respostas (mesma causa-raiz = um único achado)

| Se a LLM relatar… | Corresponde a |
|---|---|
| ISBN duplicado aceito quando título difere; unicidade depende do título; `findOne` com `title` | PR01-01 |
| Livro salvo antes de validar; erro retornado mas registro criado; cadastro inválido altera o acervo; inválido "ocupa" o ISBN e faz tentativas seguintes receberem 409 | PR01-02 |
| Cliente define `availableCopies`; disponível diferente do total na criação; disponível maior que o total ou negativo vindo da entrada | PR01-03 |
| Quantidade negativa aceita; validação por truthiness; aceita fracionário ou texto (`1.5`, `"abc"`) como quantidade | PR01-04 |

Efeitos combinados observados (não são defeitos novos): com PR01-02 + PR01-01, um livro inválido gravado com ISBN X e título T faz uma nova tentativa com o mesmo ISBN X e título T receber 409 em vez de 400 (roteiro manual, casos 8 e 9). Com PR01-02 + PR01-04, `totalCopies: -1` é gravado e não é rejeitado.
